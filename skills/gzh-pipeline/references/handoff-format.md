# 交接格式约定

## status.md 模板

```markdown
# <文章工作标题>

- 目录：gzh/<YYYY-MM-DD>-<slug>/
- 发布方式：手动（固定，不可更改）
- 当前阶段：1 选题

| 阶段 | 状态 | 执行者 | 完成时间 | 备注 |
|---|---|---|---|---|
| 0 建目录 | done | <执行者> | 2026-01-01 09:00 | 简报 12 条，2 条无出处 |
| 1 选题 | doing | <执行者> | | |
| 2 初稿 | todo | | | |
| 3 去 AI 腔 | todo | | | |
| 4 排版 | todo | | | |
| 5 封面 | todo | | | |
| 6 发布前检查 | todo | | | 必须与阶段 2 的执行者不同，或重新读取原始资料 |
| 7 人工发布 | todo | 人 | | |

## 交接记录
- <时间> <执行者>：<做了什么，留下什么问题>
```

## 各文件头部字段

所有 Markdown 交付物开头用 YAML front matter，至少包含：

```yaml
---
stage: 2-draft            # 阶段编号-名称
topic: "<选题卡里的标题方向>"
created: 2026-01-01T09:30+08:00
by: <执行者>
inputs: [00-brief.md, 01-topic-card.md]
---
```

`03-final.md` 额外包含发布需要的元数据，供 `gzh-format` 和 `gzh-precheck` 读取：

```yaml
title: "标题（公众号接口上限 32 字）"
digest: "摘要（上限 120 字）"
author: "署名（上限 16 字，可空）"
source_url: "“阅读原文”链接，可空"
theme: classic            # gzh-format 的主题名
```

## 出处的写法

- 正文里用 Markdown 链接或脚注：`据官方文档[^1]` 或 `[官方文档](https://...)`。
- `gzh-format` 会把外链统一转成上标编号和文末“参考资料”列表，因为未认证的公众号正文外链不可点击。
- 出处必须是能直接打开、内容支持该句话的原始页面；搜索结果页、模型记忆、二手转述不算出处。
