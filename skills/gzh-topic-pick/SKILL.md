# gzh-topic-pick：从简报里挑选题

输入一份简报（每条最好带原帖或原文链接）和已发文章列表，输出一张选题卡：1–3 个候选选题，每个都有切入角度、核心事实、出处链接、评分和结论。

## 输入

- **简报**：Markdown 或纯文本，每条至少包含一句摘要和一个链接。没有链接的条目只能当线索，不能当事实。
- **已发文章列表**（可选）：标题 + 日期，用于去重。没有就跳过去重，在选题卡里注明。
- **账号定位**（可选）：写什么领域、给谁看、用什么口吻。没有就按简报的领域推断，并在选题卡里写明“定位为推断”。

## 步骤

1. **筛掉不能写的条目。** 去掉：没有任何可打开链接的；只有转述、找不到一手来源的；纯八卦或纯营销稿；与账号定位无关的。被筛掉的条目在选题卡末尾列一行原因。
2. **把相关条目聚成候选。** 同一件事的多条报道合并为一个候选；几条小消息能共同支撑一个判断的，也可以合成一个候选（例如“同一周三家都发布了 X”）。
3. **为每个候选补查一手来源。** 打开简报里的链接，确认原文确实说了摘要里的话；能找到更一手的来源（官方博客、论文、代码仓库、当事人原帖）就换成一手来源。核对不了的事实标为“待核实”。需要补查原帖时，用执行环境提供的搜索或社交平台查询工具。
4. **想清楚切入角度。** 每个候选写出：目标读者是谁、他们真正关心的问题、这篇文章能新增什么（比转发新闻多出的那部分）、结论的适用边界、最强的反对意见。只是“某某发布了某某”而说不出新增价值的，结论不能是“做”。
5. **打分。** 按 `references/scoring.md` 的七个维度打 1–10 分，算加权综合分，按阈值给结论。
6. **去重。** 与已发文章主题高度重合的，除非有实质新进展，否则降为“改方向”或“不做”。
7. **写选题卡。** 按下面的格式写入 `01-topic-card.md`，按综合分从高到低排列，最多 3 个。

## 选题卡格式

```markdown
---
stage: 1-topic
created: <时间>
inputs: [00-brief.md]
---

## 选题 1：<标题方向，不是最终标题>

- 结论：做 / 改方向 / 不做（综合分 NN）
- 目标读者：……
- 读者的问题：……
- 切入角度（新增价值）：……
- 适用边界：……
- 最强反方：……
- 核心事实（每条带出处）：
  1. <事实一句话> —— [来源标题](https://...)（一手 / 二手 / 待核实）
  2. ……
- 评分：读者价值 8 / 定位匹配 9 / 角度差异 7 / 时效与长尾 6 / 出处可靠 9 / 写作成本 8 / 合规风险 9
- 建议篇幅与形式：……

## 未入选条目
- <条目> —— 原因：无链接 / 一手来源找不到 / 与定位无关 / ……
```

## 规则

- 选题卡里的每条事实都要有链接，并标明是一手、二手还是待核实。“待核实”的事实不能作为选题成立的主要依据。
- 不为了凑数而硬给 3 个；只有 1 个能写，就只给 1 个。一个都不行时如实说明，并列出缺什么资料。
- 摘要里的限定说法（“据称”“计划”“预计”）在选题卡里原样保留，不改成确定说法。
- 不评估“能不能变现”，也不预测阅读量；只判断值不值得写、能不能写准。
