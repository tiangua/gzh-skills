# gzh-precheck：发布前把关

最后一道关。先跑确定性脚本，再由审稿人逐条人工核对，两者都通过才生成手动发布包。**本技能永远不发布文章。**

## 谁来做

审稿人最好不是写稿的人。只有一个执行者时，必须重新打开每条出处原文来核对，不能凭写稿时的记忆判断“应该没问题”。

## 输入

- `03-final.md`（终稿，含 front matter 里的 title / digest / author / source_url）
- `02-draft.md` 和 `02-claims.md`（用来对比限定词和数字）
- `04-article.html`（`gzh-format` 产出）
- `05-cover-audit.json`（`gzh-cover` 产出）

## 步骤

### 1. 跑脚本

```bash
.venv/bin/python skills/gzh-precheck/scripts/check_sources.py \
  --final gzh/<目录>/03-final.md --draft gzh/<目录>/02-draft.md --claims gzh/<目录>/02-claims.md \
  --html gzh/<目录>/04-article.html --cover-audit gzh/<目录>/05-cover-audit.json \
  --online --json-out gzh/<目录>/06-precheck.json --report gzh/<目录>/06-precheck.md
```

脚本检查的内容见 `references/checklist.md` 的“脚本项”。有任何“错误”就判不通过：把问题退回对应阶段（出处问题回 `gzh-draft`，限定词或数字问题回 `zh-humanize`，HTML 问题回 `gzh-format`，封面问题回 `gzh-cover`），修完重跑。

脚本只能发现“可能有问题”的地方，例如它会把含数字但没链接的句子当作事实句。确实不是事实的（比如“第 2 节会讲”），可以改写措辞让它不含误导性数字，或者给出处；不要为了过脚本而删掉真实的限定词。

### 2. 人工核对

逐条做 `references/checklist.md` 的“人工项”，结果写进 `06-precheck.md` 末尾的勾选框。重点：

1. **逐条打开出处。** 对照 `02-claims.md`，确认每个出处页面确实支持正文那句话，数字、日期、主语一致，没有把“计划”写成“已经”。
2. **引语一字不差。** 翻译的引语注明“译文”。
3. **没有编造。** 第一人称经历、对话、采访必须来自本次人提供的材料。
4. **图片授权。** 自制、官方公开素材（注明来源）或已获授权；否则删掉。
5. **标题和摘要。** 与正文一致，不夸大，不出现正文没有的数字。

### 3. 出结论

- **通过**：脚本无错误，人工项全部勾选，警告逐条有处理说明。
- **不通过**：写清每个问题、退回哪个阶段。

### 4. 打包（只在通过时）

在第 1 步的命令后加 `--package gzh/<目录>/package`，脚本只会在没有错误时生成：

- `article.html`：粘贴用正文；
- `cover-235.png`、`cover-1x1-preview.png`：封面和缩略图预览；
- `publish.md`：标题、摘要、作者、阅读原文链接、后台操作步骤、出处清单、剩余警告。

### 5. 交给人

向人报告：结论、标题、摘要、发布包路径、出处数量、剩余警告。说明“需要你在公众号后台手动粘贴、上传封面并发布”。到此结束。

## 硬性规则

- 不调用任何发布、群发、草稿推送接口，不扫码登录公众号后台，不使用非官方接口。
- 不在没有通过的情况下生成发布包，也不把“不通过”改写成“有条件通过”。
- 不替作者补出处：找不到出处的句子，退回去删改，而不是随便找一个看起来相关的链接。
